# 분석 워크북 작성 규칙

## 생성 방법

- `.agents/scripts/gen_analysis.py` 사용: JSON 입력 → Format.xlsx 복사 + 데이터 주입 + 파이썬 마진 계산 출력
  ```
  .agents/py .agents/scripts/gen_analysis.py 데이터.json
  ```
  (`.agents/py` = conda env `electerior`의 python 3.11 심볼릭 링크. `mac-toolchain` 스킬 참조)
- JSON 구조: `[{"out": "파일명.xlsx", "meta": {...공고정보/금액/개요...}, "items": [...물품행...]}]`
- 원본 `Format.xlsx`는 절대 수정 금지. 규칙 변경 시 사용자와 협의 후 재생성

## 물품 내역 작성

- **조립 PC/서버는 부품별로 행을 펼쳐서 작성** (완제품 한 줄 요약 금지 - 사용자 지시)
- **"기타 일괄" 묶음 행 금지.** 명세서/규격서의 순번을 하나도 빠짐없이 어느 행엔가 매핑하고,
  각 행 비고에 `명세서 N항`을 적어 역추적 가능하게 한다. 작성 후 **순번 커버리지와 총수량을
  세어서 대조**할 것.
  (실사례 2026-08-20 원안기술원 R26BK01688991: 명세서 23행 중 21·22·23항을
  "기타 주변기기 일괄 1,200,000원" 한 줄에 묻었는데 그 안에 **노트북 3대(실가 642만원)** 가
  들어 있었다. 마진이 +24.3%로 나와 "검토 대상"이 됐지만 전행 대조 후 **-9.7%**였다.
  묶음 행은 추정가 금지 규칙 위반이자 판정을 뒤집는 사고다.)
- 참가자격은 공고문 본문 문구를 그대로 옮긴다. **"중소기업확인서"와 "소기업·소상공인 확인서"는
  다른 서류**이고, 나라장터 상세의 물품분류제한 필드("제한하지 않음")를 확인하지 않고
  세부품명 등록 요건을 지어내지 말 것 (같은 건에서 둘 다 틀렸음)
- 구성별 수량이 다르면(예: RAM 32GB형 2대 + 16GB형 2대) 총수량으로 적고 비고에 구성 명시
- 대안 후보(CPU 대안, 정품/병행, 규격미달 참고품)는 선택=X 행으로 함께 기록 - 토글로 시나리오 비교 가능하게
- 견적 필요 항목은 price=0 또는 참고가 + 비고에 견적처. JSON에 `"quote": true`를 넣어야 URL 검증을 면제받는다

## URL / 하이퍼링크 (2026-08-19 사용자 지적)

- URL은 셀에 텍스트로만 넣으면 Excel이 링크로 안 만든다. `gen_analysis.py`가 `cell.hyperlink`를 직접 설정하고
  파란 밑줄 서식을 입힌다 → 수정 시 이 동작 깨뜨리지 말 것
- **검색결과/카테고리/홈 URL 금지.** 상품 상세 URL만. 상세 규칙은 `price-research` 스킬의 "URL 규칙" 참조
- 선택=O 행에 불량 URL이 있으면 생성 시 `ERROR: ... URL 불량` 출력 — 무시하지 말고 실제 상품을 다시 찾을 것
- 기존 파일 일괄 보정·감사: `.agents/scripts/fix_links.py [--audit] '20260819/*.xlsx'`
- "요구 사양" 열은 **RFP(공고) 요구 조건**만 기록. 선택 제품 모델명은 품명에 적고, 제품 스펙은 요구 사양 칸에 섞지 말 것 (2026-08-19 대구대 PC: 제품 스펙을 요구 사양으로 기재해 대조 자체가 안 됐음)
- 선택(O) 행은 RFP 행 대조(특히 I/O PORTS 등 포트 조건) 후 비고에 **충족/확인필요/미달** 기록. 미달은 sel=X 필수

## 발주처 질의 회신을 워크북에 반영할 때 (2026-08-25)

**회신은 '리스크 해소'가 아니라 '원가 재계산 트리거'다.** 규격 모순을 질의해 답을 받으면
그 즉시 `[완화 후보]`에 적어둔 시나리오 중 어느 것이 열렸는지 판정하고 **선택(O) 행을 다시 고른다.**
회신을 개요에만 적고 물품행을 안 건드리면 반영한 게 아니다.

- 실사례 KAIST R26BK01690151: 규격서가 `7000WX 시리즈`(정격 DDR5-5200)와 `메모리 6400MHz`를
  동시에 요구해 성립 불가였다. 회신이 **①6400 모듈 납품 + 실동작 5200 인정** ②9985WX 상향 허용
  둘 다 열어줬고, ①을 타면 CPU가 12,299,990 → 9,861,490으로 내려가 **마진 6.9% → 11.1%**(기준 10% 통과).

### 회신 문구는 문자 그대로 읽는다 — '동작 완화'와 '표기 완화'는 다르다

`"6400MHz 메모리를 **납품하되**, 실제 동작 속도가 5200MHz로 적용되는 구성도 충족"`은
**모듈 표기속도를 낮춰도 된다는 뜻이 아니다.** 여기서 DDR5-5600/4800으로 갈아타면 규격 미달이다
(그쪽이 -205만/-369만으로 더 싸서 오독 유인이 크다). 완화된 것은 *CPU 정격 제약*이지 *부품 등급*이 아니다.
→ 규격미달 행은 X로 유지하고, 비고에 **"회신은 6400 납품을 전제하므로 여전히 부적격"**을 남겨
다음 사람이 같은 오독을 못 하게 막는다.

### 반영 시 같이 적을 것 (출처가 없으면 회신은 근거가 아니다)

개요에 `[발주처 공식 회신]` 절을 만들고 **회신자 성명·소속·이메일·회신일시 + 원문 인용**을 적는다.
규격서에 `"상기에 기술되지 않은 내용 등은 수요기관의 요청 또는 해석에 따른다"`류 조항이 있으면
그 조항을 근거로 함께 인용하고, **입찰사양서에도 회신 내용을 인용 기재**한다
(구두·메일 해석은 서류에 안 적으면 규격심사에서 증명되지 않는다).
미회신 질의가 남아 있으면 `[미회신 질의]`로 분리해 **조회 시각과 함께** 적는다.

## 이율(투찰율)

- **낙찰하한율이 공고에 명시되면 이율 = 하한율** (적격심사 87.995%, 소액수의·제한적최저가 88% 등)
- 최저가낙찰제(하한 없음): 기본 0.96으로 계산하되 0.88/0.96 복수 시나리오를 요약·보고에 병기
- 이율·부대비용은 입력셀(노란 배경)이므로 사용자가 조정하면 자동 재계산됨을 안내

## 파일명

- 분석 원본: `YYYYMMDD/YYYYMMDD_공고번호_짧은이름.xlsx` (날짜 폴더 체계, 2026-08-19 사용자 재편. gen_analysis.py가 오늘 날짜 폴더 자동 생성, GEN_OUTDIR 환경변수로 오버라이드)
- 날짜 폴더에는 그날 받은 KBID 맞춤공고 목록(.xls)도 함께 보관된다
- **공유/납품용 사본: `기관명_공고명.xlsx`** (사용자 선호. 숫자 파일명 금지)

## 보고 형식

- **마진율 내림차순 표**: 공고 | 공고번호 | 마감 | 투찰가(이율) | 원가 | 마진율 | 판정
- 반드시 명시: 견적 필요 항목, 시황 리스크, 참가자격 미확인, 마감 임박(48h 이내), OCR 기반 데이터, **규격 미달·확인필요 항목**
- 판정: 마진율 기준(기본 10%) + 참가자격·납기·규격 충족도 종합

## 물품행 20행 제한 — 2026-08-21 해제됨

`Format.xlsx`의 물품 내역은 26~45행(20행)뿐이라 다품목 공고에서 행이 조용히 잘렸다
(충북대 컴퓨터서버 R26BK01689847은 11품목을 부품별로 펼치면 **82행**이다).
`gen_analysis.py`에 `_expand_item_rows()`를 넣어 items가 20행을 넘으면 45행 아래로
행을 삽입하고 **합계 SUM 범위·수익성 수식·병합범위를 전부 재작성**한다.
openpyxl의 `insert_rows`는 수식도 병합범위도 자동 보정하지 않으므로 직접 처리한 것이다.

- 부대비용 셀이 `B50`에서 `B(50+extra)`로 밀리므로, 워크북을 손으로 읽는 스크립트는
  **A열에서 '상품가격 합계' / '부대비용' 라벨을 찾아 행을 잡아야 한다.**
  `audit_prices.py`의 `_layout()`이 그 방식이다(예전엔 26~45·B50 고정이라 TypeError로 죽었다).

## 행 번호를 고정으로 잡으면 죽는다 — `patch_items.py` 수정 (2026-08-25)

사용자가 **엑셀에서 물품행을 지우면 아래 블록이 통째로 위로 밀린다.** KAIST R26BK01690151에서
규격미달 메모리 2행을 지우자 `상품가격 합계`가 46→44행, `부대비용`이 50→48행이 됐고,
`ws["B50"]`이 **`'=B16'` 문자열**을 물어 `old_cost` 계산이 `TypeError: int + str`로 죽었다.

- `patch_items.py`에 `_layout()`을 넣어 **A열에서 '상품가격 합계'·'부대비용' 라벨로 행을 찾는다**
  (`audit_prices._layout()`과 같은 규칙). `_num()`으로 숫자 아닌 셀은 0으로 방어하고,
  items가 블록 크기를 넘으면 쓰기 전에 ERROR로 중단한다(조용한 절단 방지).
- 같은 이유로 **`edits`의 키(행 번호)도 안전하지 않다.** 사용자가 중간을 손돈 뒤에는
  패처를 돌리기 전에 반드시 현재 행 구성을 다시 읽고, 비고만 고치는 수준이면
  **품명으로 행을 찾아 openpyxl로 직접 쓰는 쪽이 안전하다**(블록 전체를 다시 쓰지 않으므로).
- 저장 직전에 mtime을 보고, 내가 마지막으로 저장한 시각보다 새로우면 **사용자가 끝어든 것**이다.

## 감사(audit_prices)가 못 보던 두 가지 — 2026-08-21 수정

1. **앵커 URL을 단 견적 행을 '전건 실가'로 오판했다.** ETRI EA20261919(DELL 정품 GPU)와
   KISTI PM9D3a E1.S는 실제로는 견적이 필요한데 앵커 상품 URL이 붙어 있어 `url_problem()`을
   통과했다. 이제 **vendor/비고의 '견적' 표기**를 먼저 보고 추정 행으로 계상한다.
2. **견적 미확보를 0원으로 넣은 행은 어느 게이트에도 안 잡힌다**(line=0이라 est_amount에
   안 들어간다). 총원가가 '하한'인데 마진율은 확정치처럼 보인다. 이제 `zero_quote_rows`로
   따로 세어 표에 `↓ +견적0원 N행`으로 표시한다. **↓가 붙은 건의 마진율은 실제보다 좋게 나온 값이다.**
3. 반대로 **사내 매입가표(티어 A)는 URL이 없어도 확정 원가**다(price-research "URL 규칙" 예외).
   vendor에 '당사 매입'·'매입가'·'사내'가 있으면 추정으로 세지 않는다.

## 부대비용은 원가에서 뺀다 — 2026-08-21 사용자 확정 (AGENTS.md 규칙 15)

`gen_analysis.py`는 이제 `meta.extra_cost`를 받아도 **0으로 강제**하고 stderr에 `NOTE:`를 찍는다.
마진율 기준은 `상품가격 합계`뿐이다.

**왜 이게 규칙이 됐나** — 부대비용은 정의상 추정치라 규칙 1(추정가 금지)과 충돌하는데,
게이트가 물품 행만 검사해서 그대로 통과했다. 그리고 건별 자의성이 판정을 뒤집었다:

| 공고 | 부대비용 포함 | 제외 | 차이 |
|---|---|---|---|
| GIST 워크스테이션 메모리·저장장치 | -12.5% | **-1.1%** | 부대 300만이 11.4%p를 먹었다 |
| KAIST 고성능 GPU 서버 | 7.5% | **10.9%** | 기준 마진율 10% 통과 여부가 갈렸다 |
| 국과연 GPU 워크스테이션 | -6.3% | -4.7% | |
| 충북대 데스크톱 | -23.2% | -21.1% | |

→ **이행비용은 개요의 리스크 항목으로만 적는다.** 다만 그 근거 문장은 지우지 말 것
  (투찰가 결정 시 사람이 판단할 재료다). 견적처·단가가 붙는 실물(보증연장·설치지원 등)은
  부대비용이 아니라 **물품 행(sel=O)** 으로 계상한다.

소급 적용 이력: `20260821/` 12건의 부대비용 셀을 0으로 바꾸고 개요에 규칙 변경 주석을 덧붙였다.
제거 전 값은 `ChangeLog_부대비용제외_20260821.txt`에 남겼다(복원용).

## 견적을 0원으로 넣으면 게이트가 "전건 검증 완료"를 내줬다 (2026-08-21, 수정됨)

규칙 1이 "게이트를 통과해야 보고할 수 있다"로 막아둔 경로에 **정확히 반대 방향의 구멍**이
있었다. 추정가를 *써넣으면* 걸리는데, 견적 미확보를 **0원으로 비워두면 아무 데도 안 걸렸다.**

송원대 R26BK01686155이 실제로 이렇게 통과했다 — 선택 6행 중 3행(크롬북 40대·CEP 230개·
연수 3회)이 0원 견적인데 원가가 충전보관함 378만원뿐이라:
- `gen_analysis.py` → `gate:"OK"`, `all_verified:true`, `margin_rate:96.4`, `reportable:true`
- `audit_prices.py` → `전건 실가 / 보고가능`
- 대시보드 → **96.4% 초록색, 목록 최상단**

세 군데 다 고쳤다. 판정 기준은 하나다: **0원 견적행이 하나라도 있으면 총원가는 '하한'이고
마진율은 '상한'이다. 그건 마진율이 아니다.**
- `gen_analysis.py`: `zero_quote_rows`/`cost_is_lower_bound`를 `price_basis`에 싣고
  `reportable=False`, `gate="PROVISIONAL"`
- `audit_prices.py`: 가격근거를 `원가미확정 +견적0원 N행` + `← 보고금지`
- `dashboard_view.py`: `원가 미확정`(muted) + **`sort=None`** — 가린 값으로 줄 세우지 않는다

곁가지로 두 개 더 나왔다:
- **마커 탐지가 표기 흔들림에 깨졌다.** 감사가 비고의 `"견적 필요"`(공백 O)만 찾는데 워크북
  표기는 `"견적필요"`(공백 X)였고, **품명 칸(`[견적필요] …`)은 아예 안 봤다.** 지금은 공백을
  지운 뒤 품명·판매처·비고를 모두 본다. bare `"견적"`으로 넓히면 '견적 별도' 같은 문구를 단
  실가 행까지 오탐하므로 마커 토큰(`견적필요`/`견적처`)만 쓴다
- **`audit_prices.py '날짜폴더/*.xlsx'`가 네 폴더 전부 크래시하고 있었다.** 국보연CPU부품
  파일 단가 셀에 공백 문자 `' '`가 들어가(엑셀 수기 편집 흔적) `4 * ' '`가 문자열 반복이 돼
  `TypeError`로 죽었다. **규칙 6이 보고 근거로 삼으라는 바로 그 명령이다.** 지금은 숫자가
  아니면 0으로 내리고 `숫자아님` 문제 행으로 드러낸다. 사용자가 엑셀을 병행 편집하므로
  셀 타입은 항상 방어할 것
