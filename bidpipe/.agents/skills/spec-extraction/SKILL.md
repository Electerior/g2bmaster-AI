# 규격서(첨부파일) 처리

## 다운로드

- 나라장터 첨부 URL 패턴 (fetch로 바로 다운로드, 로그인 불필요):
  `https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?bidPbancNo={공고번호}&bidPbancOrd={차수:000}&fileType=&fileSeq={N}&prcmBsneSeCd=01`
- fileSeq는 첨부 목록 순서(1부터). G2B Masters 다이얼로그의 링크 href에서도 추출 가능
- 매직바이트로 형식 판별: `2550`=PDF, `d0cf`=HWP(OLE), `504b`=HWPX(zip)

## 형식별 추출 (파이썬: `.agents/py`)

| 형식 | 도구 | 주의 |
|---|---|---|
| PDF (텍스트형) | pypdf | |
| HWP | `hwp5html` | **hwp5txt는 표 내용 누락**(`<표>`로만 출력). 규격표는 반드시 hwp5html → xhtml 태그 제거 |
| HWPX | zipfile + ElementTree | `Contents/section*.xml`의 `t` 태그 텍스트 수집. **반드시 `''.join(el.itertext())`** — `el.text`만 읽으면 줄이 통째로 사라진다(아래 사고) |
| 스캔 PDF | `pdftoppm -png -r 200` → `tesseract 이미지 out -l kor+eng --psm 6` | OCR 오독 가능 - 분석 파일에 "OCR 기반, 원문 재확인 필요" 명시 |

- 규격서가 이미지뿐이고 PDF 공고문이 길면 공고문에 사양이 요약된 경우도 있으니 먼저 grep
- 배포용(암호화) HWP은 hwp5 계열로 안 열림 → PDF 변환본 우선, 없으면 한컴오피스(설치됨) 수동 확인

## 추출 후 확인할 것

- 물품별: 품명/수량/핵심 사양/동등이상 허용 여부
- 특이조건: 현장설치, 기존장비 철거, SW 설치(교내 라이선스 등), 네트워크 작업, 벤치마크 제출, 교육
- 요구 서류: 정품 공급확약서, 기술지원확약서, 직접생산확인증명, 규격검토확인서(사전 제출 마감 주의)
- 규격서 오류 사례 존재: CPU-보드 소켓 불일치(동남보건대), 코어수 오기(코리아텍 265K를 24코어로 표기)
  → 비고 기록 + 발주처 문의 권장

## HWPX는 `el.text`로 읽으면 규격 줄이 조용히 사라진다 (2026-08-21 KAIST 사고)

`extract_specs.py`의 HWPX 파서가 `<hp:t>`에서 `el.text`만 읽고 있었다. ElementTree에서
**요소에 자식(markpen/lineBreak/ctrl 등)이 있으면 `.text`는 '첫 자식 앞'까지만 반환하고
나머지는 자식의 `.tail`에 들어간다.** 그래서 서식이 걸린 줄이 통째로 유실됐다.

KAIST R26BK01690151 규격서에서 사라진 3줄:
- `나. 고성능 CPU` → `3) L3 Cache: 256MB`
- `다. 메인 메모리` → `1) Memory: DDR5 ECC 64GB`, `2) Clock speed: 6400MHz`

결과: '메모리 속도 미지정'으로 오판 → 규격 미달 DDR5-5600 선택 → 마진이 실제 7.5%인데
**11.0%로 부풀어 '검토 대상'으로 보고**됐다. 텍스트만 봐서는 아무 이상이 없어 보였다.

- 반드시 `''.join(el.itertext())`로 tail까지 회수한다. `t` 내부는 더 파고들지 않는다.
- 구 파서가 뭘 놓쳤는지 감사: `extract_specs.hwpx_dropped_by_old_parser(경로)`

## 추출물은 항상 자가검증한다 — 번호 연속성 검사 (2026-08-21 추가)

**"눈으로 읽어서 멀쩡하면 통과"는 방어가 못 된다.** 위 사고는 결과 텍스트가 완벽히
자연스러워 보였다. 유일한 흔적은 `다. 메인 메모리 : 8개` 아래가 `3)`부터 시작한다는 것뿐이었다.

`extract_specs.py`가 추출 직후 `audit_extraction()`을 자동 실행한다:
- 한글 항목머리(가./나./다.) 아래 아라비아 열거가 **1)부터 연속인지** 검사
- 첫 항목이 1)이 아니거나 중간을 건너뛰면 `[!] 누락의심` 경고를 **stdout으로** 출력
  (stderr로만 내면 보고 경로에서 증발한다 — 규칙 1의 `gate:BLOCKED`와 같은 이유)
- 소스 무관하게 동작하므로 HWP·PDF·OCR 결과에도 그대로 쓴다

**경고가 뜨면 원문(PDF 변환본·미리보기)으로 해당 구간을 직접 대조하기 전에는 분석에 들어가지 말 것.**

## 규격 요약·제안 대조 규칙 (2026-08-19 대구대 PC 사고 후 추가)

- 추출한 규격표 **전 행**을 요약에 실 것. 행을 골라 요약하면 조건이 조용히 사라진다.
  (실사례: I/O PORTS 행(2 HDMI·PS/2·RGB)이 요약에서 유실 → 메인보드 HDMI 1개 제품 선택 사고)
- **행 번호를 세어라.** 규격서의 `1) 2) 3)`, `가. 나. 다.`, 명세서 순번을 워크북 '요구 사양'에
  옮길 때 번호까지 같이 적고, 마지막에 **개수를 원문과 대조**한다. 유실은 내용이 아니라
  번호에서 먼저 드러난다 (2026-08-21 KAIST: 메모리 항목이 3)만 남아 있었다).
- "동급 이상으로 자유롭게 제안 가능"의 정확한 의미: **모델·브랜드 선택 자유, 개별 사양 하향 불가**.
  평가표에 "제시규격 대비 부족 감점" 구조가 있으면 부족 = 점수 감점이지 허용이 아님.
- I/O PORTS 같은 행은 **메인보드(또는 케이스·전원) 선택의 제약 조건**이다.
  메인보드 행이 칩셋 한 줄만 쓰여 있어도 포트 수는 보드 후면 I/O로 충족해야 하고, DP≠HDMI.
  어댑터 보완은 발주처 인정 여부가 아니라 원칙적으로 미달로 처리.
- 가격 조사 후 **선택(O) 행 전체를 규격표와 행 대조**하고, 결과(충족/확인필요/미달)를 물품 비고에 기록.
  미달이면 sel=X 전환 + 현장설명회·질의회신 확인 항목으로 기록.

## 규격 전행 유실이 또 났다 — 2026-08-21 KAIST R26BK01690151

대구대 I/O PORTS 사고(2026-08-19)와 **동형 재발**이다. 규격서 Ⅲ-1-다는 이렇게 3줄이었다:

```
다. 메인 메모리 : 8개
  1) Memory: DDR5 ECC 64GB
  2) Clock speed: 6400MHz        ← 이 줄이 요약에서 사라졌다
  3) ECC기능 기반 데이터 무결성 확보
```

요약에 `다.메모리 8개: ECC 기반 데이터 무결성`만 적었고, 그 결과 DDR5-**5600** RDIMM을
선택해 원가를 205만원 과소계상했다(마진 11.0% → 실제 7.5%). 같은 항목에서 CPU의
`3) L3 Cache: 256MB`도 유실됐다(7985WX가 우연히 256MB라 결과적으로만 무사했다).

**재발 방지 규칙(기존 규칙의 구체화):**
- 규격서의 `가/나/다/라` 항목은 **하위 번호 1)2)3) 까지 전부** 요약에 옮긴다.
  상위 항목명만 남기고 하위를 요약하면 수치 조건이 통째로 사라진다.
- 요약 작성 후 **규격서의 숫자 토큰(GHz/MHz/MB/GB/TB/W/mm/개/코어)을 정규식으로 뽑아
  요약에 다 들어갔는지 대조**하라. 사람이 눈으로 세면 놓친다.
- 선택(O) 행의 `spec` 칸에도 그 수치가 들어가야 한다. spec에 없으면 대조 자체가 안 된다.

## 규격서 내부 충돌은 '오기'가 아니라 **판정 스윙**이다 — 반드시 시나리오로 분리

2026-08-21 하루에 3건 나왔다. 전부 마진율을 두 자릿수 %p 흔든다.
| 공고 | 충돌 | 스윙 |
|---|---|---|
| KAIST R26BK01690151 | `7000WX-Series` + `메모리 6400MHz` — **7000WX는 공식 DDR5-5200이라 성립 불가** | 3.5% ~ 11.0% |
| 충북대 데스크톱 R26BK01690110 | 본문 CUDA 21,760 vs 표 10,752 / 본문 SSD 2TB vs 표 8TB | -23.2% ~ +15.2% |
| KAIST R26BK01690151 | `2000W 80PLUS PLATINUM` — 참고제품(ASUS ET900A X9)엔 없는 조합(1650W 플래티넘 / 2000W 골드) | 베어본 경로 개폐 |

→ 충돌을 발견하면 **어느 쪽이 맞는지 고르지 말고 시나리오 표를 만들어라.**
  각 시나리오의 총원가·원가율·손익분기 투찰율·마진을 다 내고, 질의 항목으로 올린다.


## HWP 추출이 조용히 전부 실패하고 있었다 — `.agents/py`가 심볼릭 링크라서 (2026-08-21)

`extract_specs.from_hwp()`가 `os.path.dirname(sys.executable)`로 `hwp5html`을 찾았는데,
`.agents/py`는 conda python으로 가는 **심볼릭 링크**라 `sys.executable`이 링크 경로 그대로
잡힌다. 결과적으로 `/Users/hanbin5/Documents/Electerior/.agents/hwp5html`을 찾다 실패했다.

증상이 고약하다: **종료코드는 0이고, .txt 파일도 정상 생성되며, 번호 연속성 검사도 통과한다.**
HWP 첨부 자리에만 `[HWP-FAIL ... No such file or directory]` 한 줄이 들어가 있을 뿐이라
PDF 변환본이 같이 첨부된 공고에서는 전혀 눈치챌 수 없다.
(가천대 R26BK01686166: 첨부 4개 중 HWP 3개가 전멸해 **규격서 본문이 통째로 비어 있었는데**,
공고문 PDF 변환본이 있어서 5,980자가 나왔다 — 겉보기엔 정상이었다. 고친 뒤 14,871자.)

수정: `_hwp5html()`이 `os.path.realpath(sys.executable)` → conda/venv → `.agents/pyenv39/bin`
→ `shutil.which` 순으로 찾고, 전부 실패하면 시도한 경로를 붙여 예외를 던진다.

**추출 결과에 `[HWP-FAIL`·`[PDF-FAIL`이 있는지 grep하는 것을 습관화할 것.** 첨부 개수와
추출된 섹션 개수가 맞아도 내용이 비어 있을 수 있다.

## 실행법 주의: `extract_specs.py`는 파일이 아니라 **디렉터리**를 받는다

`extract_specs.py <SPECDIR> [공고번호...]` — 두 번째 인자는 `SPECDIR` 아래의 **폴더명**이다.
파일 경로를 바로 주면 `NotADirectoryError`로 죽는다.
`.agents/py .agents/scripts/extract_specs.py 20260821/specs 가천대약대_R26BK01686166`

## 품명 자체에 부속이 숨어 있다 — "케이블&커넥터포함", "브라켓포함"

규격서 품명 칸의 `유선 MIC / **케이블&커넥터포함**`처럼 **품명 문자열 안에 별도 구매 품목이
들어 있는 경우**가 있다. 사양 칸만 읽고 넘어가면 원가에서 빠진다.
(젠하이저 XS1은 케이블 미포함 출하라 XLR 케이블 2개가 실제로 추가 원가였다.)
→ 품명·사양 양쪽에서 `포함`, `일체`, `세트`, `옵션` 토큰을 훑고 각각 행으로 펼칠 것.
