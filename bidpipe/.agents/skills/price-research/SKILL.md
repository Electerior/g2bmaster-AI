# 가격 조사 규칙

## 원칙

- **추정가 사용 금지. 전 품목 실판매가 + 출처 URL.**
  (실사례: 부산대 GPU서버 - 추정 시 -4.9%, 실가격 조사 후 -51.9%. 추정은 판정을 뒤집는다)
- 실판매가가 존재하지 않는 항목만 "견적 필요"로 표시하고 **견적처(업체명/연락처/URL)를 기록**
- 부가세·배송비 포함 실구매가 기준. 대량 납품 건은 재고/물량 확보 리스크를 비고에
- B2B 대량구매 할인 여지(통상 5~15%)는 마진에 선반영하지 말고 비고로만

## URL 규칙 (2026-08-19 사용자 지적 — 필수)

- **반드시 상품 상세 페이지 URL을 기록한다.** 검색결과·카테고리·사이트 홈 URL 금지.
  - ✖ `search.danawa.com/dsearch.php?query=...`, `prod.danawa.com/list/?cate=...`,
    `search.11st.co.kr/...`, `www.coupang.com/`, `www.dell.com/ko-kr/shop/`, `prod.danawa.com/info/`(pcode 없음)
  - ✔ `prod.danawa.com/info/?pcode=94024931`, `coupang.com/vp/products/...`,
    `smartstore.naver.com/<shop>/products/...`, `compuzone.co.kr/product/product_detail.htm?ProductNo=...`
- 검색 결과를 그대로 붙이면 가격이 특정 상품에 묶이지 않아 **단가 자체가 검증 불가**해진다.
  (실사례 2026-08-19 거래소 노트북: 검색 URL로 적은 B유형 221만원이 실재하는 상품과 무관했고,
   실제로 규격을 충족하는 모델은 285만원이었음 → 원가 64만원/대 과소평가)
- 검색으로 찾았으면 **개별 상품을 클릭해 들어가 pcode를 확보**하고, 그 상세페이지의 스펙으로 RFP 대조한다
  (다나와 검색 목록 스펙은 해상도·OS·배터리가 생략되어 있어 규격 판정에 사용 불가)
- 검증기: `.agents/scripts/gen_analysis.py`의 `url_problem()` — 불량 URL은 생성 시 ERROR 출력.
  기존 파일 감사는 `.agents/scripts/fix_links.py --audit '20260819/*.xlsx'`
- 가격 DB에도 같은 규칙 적용. 사내 매입가표 기반 항목만 URL 없음 허용(vendor에 채널 명시)

## 다나와 통합 카탈로그 pcode ≠ 최저가 (2026-08-20)

같은 사양이라도 다나와에는 **SKU 미지정 통합 카탈로그**와 **정식 SKU 개별 카탈로그**가 따로 있고,
정식 SKU 쪽이 더 싼 경우가 있다. 검색 상단만 보고 잡으면 원가를 과대평가한다.

- 실사례: 갤럭시북5 프로 16 Ultra7 258V/32GB/1TB
  - 통합 카탈로그 `pcode=77623907` → 3,196,990원
  - 정식 SKU `NT960XHA-K71AR pcode=72473858` → **2,898,000원** (-29.9만)
- 제품명이 `제조사 + 시리즈 + CPU` 수준에서 끝나면 통합 카탈로그다. **모델코드(-K71AR 등)까지
  붙은 항목을 따로 검색**해 비교할 것.
- 다나와 상세의 `판매유형: 제조사기본상품`이 정품 판정 근거다. '구성변경상품'은
  개봉 후 SSD/RAM을 갈아끼운 것이라 **정품·신품 요구 공고에서 사용 불가**.

## 상위 옵션이 붙은 SKU를 최저가로 착각하지 말 것

워크스테이션·서버처럼 옵션 폭이 큰 제품군은 **규격서가 요구하지 않은 상위 부품이 포함된 SKU**가
검색 상단에 뜬다. 규격서에 그 항목 요구가 아예 없으면 하위 SKU가 정답이다.

- 실사례(극지연 11-1): 규격서에 **GPU 요구가 한 줄도 없는** 모바일 워크스테이션
  - RTX PRO 5000 24GB SKU `21RQS03X00` → 10,500,000원 (예산 상한 10,230,000 초과)
  - 나머지 전 조건 동일한 RTX PRO 4000 16GB SKU `21RQS03Y00` → **6,601,000원**
  - 이 한 건의 해석 차이가 공고 전체 마진을 +143만 ↔ -190만으로 뒤집었다.
- 단, 하위 SKU는 **OS 미포함(프리도스)**이거나 워런티 등급이 낮은 경우가 많다.
  다나와 상세의 `운영체제(OS)` 항목을 반드시 확인하고 Win 라이선스·워런티 업그레이드를
  별도 행으로 원가에 넣을 것.

## 가격이 공개 안 되는 품목 — 추적 4채널 (2026-08-20 구축)

서버 베어본·엔터프라이즈 스토리지처럼 시중가가 안 걸리는 품목은 **"못 찾는 문제"가
아니라 "관측 채널이 다른 문제"**다. 공개가 품목은 URL 재조회로 추적되지만,
불투명 품목은 URL이 없으니 추적 메커니즘 자체를 바꿔야 한다.

**불투명 가격은 "구하는" 게 아니라 상한을 좀혀가는 것이다.**

### 채널 A — 조달 종합쇼핑몰 계약단가 (최우선)

⚠ 구 도메인 `shopping.g2b.go.kr`은 **죽었다**(applet로 리다이렉트 후 타임아웃).
현재 살아있는 건 **`shop.g2b.go.kr`**. 로그인 없이 순수 fetch로 뚚린다.

```

headers: Content-Type: application/json;charset=UTF-8 / Menu-Info: {}
body:    {"searchVO":{"dtlsPrnmNo":"4321150102","recordCountPerPage":100,"currentPage":1}}
→ rsltList[].ctrtUprc(계약단가) / mnftrEtpsNm(업체) / itemIdnfNm(규격)
  / pdctAtrbNm+pdctAtrbCdDtlNm(속성표) / ctrtItemMngNo(고정 URL 생성용)
상세: https://shop.g2b.go.kr/link/GMSF001_01/?ctrtItemMngNo=<값>   ← 비로그인 재방문 가능
```

그래픽용어댑터 95 / 기억유닛 47 / SSD 13 / RAID 3)

**이 값을 원가 행에 넣지 말 것.** 계약단가는 소매가보다 비싸다. 쓰임새는 셋이다.
1) **수요기관이 예산을 짜는 근거** (서버 공고 예산은 다나와가 아니라 여기서 나온다 — 규칙 12의 서버판)
2) **우리가 이겨야 하는 천장** (bound=upper)
3) **계약업체 명단 = 경쟁사 지도** (스마일서브·코리아넷·세오·AIS·케이티엔에프·웰메이드컴퓨터)

⚠ 키워드 검색은 OR다. `H100` 넣으면 **울타리·소독기까지 44,844건**이 나온다.
반드시 `dtlsPrnmNo`로 좁혀라. 공식 오픈API도 있다(`data.go.kr/data/15129471`,
`getMASCntrctPrdctInfoList`, 무료·자동승인, `cntrctPrceAmt` 포함) — 비공식 API가 깨지면 이쪽으로.

### 채널 B — 구성 차분 역산 (올서버 카탈로그)

완제품 가격표는 그냥 가격표가 아니라 **(구성 벡터, 가격) 데이터셋**이다.

- **단일 부품 차이 쌍의 가격차 = 그 부품의 그 채널 실거래가.** 근거 URL이 2개 붙어 재현 가능
  → acquisition=derived, bound=point, tier B
- **완제품가 − 값을 아는 부품가 합 = 베어본 상한.** 일부를 못 빼도 상한은 유효하다
  (덜 뺀 만큼 잔액이 더 클 뿐) → bound=upper

```
python .agents/scripts/delta_infer.py            # 리포트
python .agents/scripts/delta_infer.py --register # 가격 DB에 관측으로 기록
```

실측(2026-08-20): 완제품 플랫폼 49개 → 차분 쌍 4건 + 베어본 상한 18건.
예: `DL380 G11` Xeon-S 4514Y→4516Y+ = **+1,544,000원**,
`GIGABYTE G294-S41 / RTX5090 AI 서버` 35,000,000 − CPU 2,713,000 = **잔여 상한 32,287,000원**
(미차감: 256GB DDR5, 960GB SSD×2, RTX 5090 — 이걸 공개가로 더 빼면 상한이 더 좀혀진다)

주의: 차분은 **보수적으로** 돌려야 한다. 구분자는 `' / '`(공백 포함)고,
라벨 없는 조각(`10Gb 2P`, `800W×2`)을 버리면 "네트워크도 다른 두 SKU"가
"CPU만 다른 쌍"으로 보여 가격차 전액이 CPU 탓으로 잘못 돌아간다.
올서버 `mainCategory`가 다르면 다른 제품군이니 쌍으로 쓰지 말 것.

### 채널 D — 개찰결과 역산 (공짜 오라클)

```
낙찰가 W ≥ Σ(낙찰자 원가)   →   Σ(불투명 행) ≤ W − Σ(공개가 행) − 부대비용
```

불투명 행이 하나뿐인 공고는 단가 상한이 바로 나온다. 진 공고가 오히려 정보다 —
낙찰가가 우리 추정보다 낮으면 우리 불투명 항목 추정이 과대했다는 뜻이고,
그 사실이 다음 견적 협상의 근거가 된다.

```
python .agents/scripts/opaque_bounds.py             # 불투명 행 현황 + 역산 상한
python .agents/scripts/opaque_bounds.py --register  # 상한 관측으로 기록
```

한계를 같이 읽어라: 낙찰자 BOM이 우리와 같다는 보장은 없다. 그래서 '가격'이 아니라 '상한'이다.
예산이 음수로 나오면 낙찰자가 역마진이거나 우리 확정가가 과대한 것 — 원가 재검토 대상.

### 견적은 "이벤트"가 아니라 "만료되는 자산"이다

견적을 note 문자열에 묻어두면 **넣는 순간 화석**이 된다. 반드시 같이 적는다:
`견적처 / 담당자·연락처 / 발급일 / valid_until / qty_tier(수량구간) / 구성 / 부가세·운송·설치 포함여부 / 원문 파일 경로`

- **만료되면 자동 강등**: `valid_until` 지나면 tier A → D, 게이트가 BLOCK한다
- **건별 견적은 버린다.** 마감 3일짜리 공고에서 견적 못 받는다.
  **분기 단가표(딜러 프라이스리스트)**를 미리 받아두는 게 유일한 해법이다
  (HPE 파트너 단가표 080-703-0706 / 아이티마야·올서버·엑스디노드 딜러가 / NVIDIA는 리더스시스템즈)

## 채널 지도 — **다나와만 보면 서버는 없다고 착각한다** (2026-08-20)

다나와는 **컸슈머 리테일 색인**이라 브랜드 서버·엔터프라이즈 스토리지·서버 CPU가 거의 안 잡힐다.
"견적 필요"로 넘기기 전에 **서버 전문몰을 반드시 먼저 확인할 것.**
(실사례: Xeon Silver 4510·EPYC 9335·DL380을 다나와에서 못 찾아 "국내 미유통"으로 결론했는데,
 올서버에는 가격까지 붙은 상품이 592개 있었다)

## "X는 존재하지 않는다"는 단일 출처로 말하지 않는다 (2026-08-25)

가격을 틀리면 마진이 틀리지만, **부정 존재 주장("그런 옵션은 없다", "그 조합은 안 나온다")을 틀리면
규격서가 틀렸다고 발주처에 알리는 단계까지 간다.** 이건 복구가 안 된다.

사례(KAIST R26BK01690151): 개요에 "ASUS ET900A X9의 PSU 옵션은 1650W PLATINUM 또는 2000W GOLD**뿐**이라
규격서의 2000W PLATINUM은 **존재하지 않는 조합**"이라고 적었고, 그 전제로 발주처에
"GOLD를 동등이상으로 인정해 달라"는 메일까지 나갔다. 근거는 **ASUS 스펙표 한 곳**뿐이었다.
전수 재확인하니 같은 제조사 자료가 **셋으로** 갈렸다:

| 계층 | ET900A X9 2000W PSU 표기 |
|---|---|
| 제조사 스펙표(global/EA/US eShop) | 80 PLUS **GOLD** |
| 제조사 개요 페이지(global) | up to 2000W **Platinum** |
| 제조사 개요 페이지(US) + ASUS 제공 유통 카피(Newegg/Icecat) | up to 2000W **Titanium** |
| 유통 SKU 필드 | P/N별로 다름 (90WS0022-M000K0=GOLD / 90WS0022-M002E0=80+ Titanium) |

교훈 셋:
1. **부정 존재 주장은 최소 3계층을 교차해야 한다** — 제조사 스펙표 / 제조사 마케팅 문구 /
   유통 SKU 구조 필드. 셋이 갈리면 "단정 불가 · P/N 확인 필요"로 적고, 절대 "없다"로 적지 말 것.
2. **워크스테이션·서버 베어본은 모델명이 아니라 P/N이 사양이다.** 같은 `ET900A X9`도
   `90WS0021-M000A0` / `90WS0022-M000K0` / `90WS0022-M002E0`이 PSU 등급이 다르다.
   견적·규격대조는 반드시 P/N 단위로 할 것.
3. **규격보다 낮은 등급을 스스로 요청하는 질의(하향 질의)는 마지막 수단이다.**
   상위 등급 SKU를 먼저 찾아보고, 그래도 없을 때만 묻는다. "불가" 회신이 오면
   규격심사 직전에 **우리가 규격 미달품을 제안했다는 기록**만 남는다.

## 갱신은 스크립트, AI는 예외만 (비용 구조)

**상품이 특정된 뒤의 가격 갱신은 판단이 아니라 결정론적 스크레이핑이다.**
갱신을 AI가 하면 상품 수에 비례해 비용이 터지지만, 스크립트가 하면 무제한 반복해도 0원이다.
AI는 (1) 상품을 찾아 규격과 대조하는 일, (2) 예외 해석에만 쓴다.

```
python .agents/scripts/price_refresh.py                 # 갱신 + 예외 리포트
python .agents/scripts/price_refresh.py --threshold 1.0 # 임계 1.0%p (기본 0.5)
python .agents/scripts/price_refresh.py --dry           # 기록 없이 조회만
python .agents/scripts/price_refresh.py --browser-in x.json  # 브라우저 결과 합류
#   ⚠ 이 모드는 fetch를 건너뛴다. 예전엔 exceptions.json의 failures를 통째로 지우는
#   버그가 있었다(2026-08-21 수정). 지금은 이전 목록을 읽어 이번 입력에 가격이
#   들어온 키만 빼고 보존한다. 입력 JSON에 `title`을 같이 실으면 불일치 검출도 동작한다.
```

- 대상은 **살아있는 공고(개찰 전)에 걸린 상품만**. 개찰이 지난 공고의 상품은 자동 은퇴된다
  → 관리 대상이 무한히 늘지 않고 상시 100개 내외로 유지된다.
- 관측 로그: `.agents/data/price/observations.jsonl` (**append-only**, 덮어쓰기 금지)
- 예외 목록: `.agents/data/price/exceptions.json`
- **워크북은 절대 수정하지 않는다.** 보고만 하고 반영 여부는 사용자가 정한다.

### 3단 티어 (2026-08-20 실측: 108개 중 89개 = 82%를 LLM 없이 커버)

1. **fetch 티어** (기본, ~30초/100개) — 다나와 100%, JSON-LD 있는 소형몰
2. **브라우저 티어** — `exceptions.json`의 `blocked:true` 건을 Playwright로.
   쿠팡·스마트스토어·G마켓·SSG·컴퓨존은 403/429/빈응답이라 여기서 처리. 역시 LLM 판단 0.
   추출 순서: JSON-LD → `meta[product:price:amount]` → 사이트별 셀렉터
   (`.total-price strong`·`.price_real`·`.ssg_price` 등). 결과는 `--browser-in`으로 되돌린다.
3. **AI 티어** — 아래 세 가지만.

### AI를 부르는 조건 (오직 이것만)

- **마진율 영향 임계 초과** — 단가 변동률이 아니라 *그 공고의 마진율을 몇 %p 흔드는가*로 거른다.
  2만원짜리가 +5.8% 올라도 175대 곱해 0.0%p면 AI가 볼 이유가 없다.
  마감 임박(D-2) 공고는 임계를 낮추고(0.5%p), 여유 있으면 높인다(3%p).
- **상품 동일성 의심** (|변동| ≥ 40%) — 시세가 아니라 URL이 다른 상품을 가리키는 건이 많다.
  가격을 받아들이지 말고 **상품이 같은지부터** 확인한다.
- **스크레이핑 실패** — 단종/가격비교 중지, 해외몰(환율 필요), URL 오타 등
- 신규 상품은 당연히 AI (규격 대조가 필요하므로)

### 스크레이퍼가 '가짜 급등'을 만드는 4가지

**"파싱이 됐다"와 "실판매가를 얻었다"는 다르다.** 아래는 전부 에러 없이 숫자를 돌려주면서
틀린 값이었다. 새 사이트를 넣을 땐 이 3개를 먼저 의심할 것.

1. **정가/할인전가를 최저가로 읽음.** 롯데온 JSON-LD `offers.price`는 *할인전* 가격이다
   (다크플래시 팬 실판매가 78,050원인데 141,900원으로 읽어 +81% 급등을 만들었다).
   → 롯데온은 fetch로 실판매가를 못 얻는다. **무조건 브라우저 티어.**
2. **봇 응답에서 할인이 붕괴됨.** 11번가는 브라우저엔 `offers.price=4,722,800`(+취소선 4,935,000)을
   주지만, fetch엔 `offers.price=4,935,000`으로 **정가와 취소선가를 같게** 준다.
   → `offers.price >= priceSpecification.price`면 봇 응답이니 브라우저 티어로 보낸다.
3. **아무 숫자나 집는 텍스트 폴백.** 컴퓨존은 상품이 삭제되면 **메인으로 리다이렉트**하는데,
   본문 첫 `N원` 패턴을 집으면 쿠폰 금액 10,000원이 상품가로 들어온다.
   → 폴백 전에 **페이지 제목이 상품명인지** 확인하라. 제목이 쇼핑몰 이름이면 상품 페이지가 아니다.
4. **최저가 배지가 죽은 매물을 가리킴** (2026-08-25). 파싱도 페이지도 맞는데 그 매물이 없다.
   다나와 `pcode=75991769`는 1위 292,850(쿠팡)이 **판매종료**, 2위 1,317,590(제플몰)이 **품절**,
   실구매 최저가는 3위 1,936,000이었다. → **1위가 2위보다 40% 넘게 싸면 의심**하고
   `bridge/loadingBridge.html` 링크를 브라우저로 따라가 판매상태를 본다.
   fetch HTML엔 최저가 1건만 오므로(몰 목록은 AJAX) 스크레이퍼 단에서는 못 막는다 —
   방어는 아래 '미검증 가격은 마진에 넣지 않는다'로 리포트 계층에 걸었다.

### '가격 패턴 미검출'은 실패가 아니라 **에스컬레이션 신호**

예전엔 여기서 영구 실패로 죽었다. 온누리음향·윤사운드는 3일 내내 '실패'였는데
브라우저로 열면 770,000₩ / 39,000₩이 멀쩡히 보였다(JS 렌더 + `₩` 표기라 정규식이 못 봤다).
→ 이제 `blocked:True`로 브라우저 티어에 넘어간다. 그래도 안 되면 그때 견적/단종으로 판정한다.
국내 쇼핑몰 빌더(영문1·그누·사이송)는 가격을 class가 아니라 **`id="price"`**로 단다.

### 미검증 가격은 마진에 넣지 않는다 (2026-08-25)

`label_mismatch`·`suspect_identity`는 **"확인 전에는 쓰면 안 되는 값"**인데, 예전엔 그 값으로
마진을 다시 계산해 리포트 맨 위에 올렸다. 그래서 **없는 판정 뒤집힘**이 매일 상단을 차지했다.

- 한밭대 GPU서버 `-37% → -344.2%` — 7개 행이 **같은 아이티마야 URL 하나**를 물고 있어
  베어본·SSD·NIC·보증·설치지원이 전부 5,000만원으로 찍혔다(상품키 붕괴의 워크북판).
- KISTI Mac mini `-1.8% → +48.4%` — 48GB/2TB 라벨에 붙은 URL이 기본형(24GB/512GB)이었다.
- 계명대 `11.6% → 19.0%` / 생기원 `-20.3% → -8.4%` — 다나와 최저가가 **판매종료 매물**이었다.

이제 `price_refresh.py`는 마진을 두 벌로 낸다.

| 필드 | 뜻 |
|---|---|
| `margin_after` | 의심 행을 **워크북 값으로 되돌린** 보수 마진. **보고는 이 값으로 한다** |
| `margin_after_unverified` | 의심 행까지 포함한 참고값. 확인 끝나기 전엔 인용 금지 |
| `n_unverified` | 그 공고에서 확인이 걸려 있는 행 수 |

화면에는 `[미검증 N행 제외 · 포함시 X%]`로 붙는다. **이 표시가 있으면 그 공고의 진짜 숙제는
시세가 아니라 워크북 URL 수정이다.**

⚠ 워크북 단가가 0원인 행이 있으면 변동률이 정의되지 않는다. 예전엔 여기서
`ZeroDivisionError`로 리포트 전체가 죽었다(2026-08-25 수정). 지금은 `0원행`으로 표시되고
`suspect_identity`에 올라간다.

### 라벨↔URL 불일치 자동 검출 (`label_mismatch`)

임계 초과 건의 다수는 시세가 아니라 **워크북 라벨과 URL이 다른 상품**인 경우다.
`price_refresh.py`가 상품 페이지 `<title>`을 관측에 같이 저장하고(`page_title`)
용량(GB/TB 환산)·브랜드 토큰을 워크북 라벨과 대조해 `exceptions.json`의
**`label_mismatch`** 절로 따로 뽑는다. 여기 뜬 건은 **시세 변동으로 보고하면 안 되고 URL을 고쳐야 한다.**
(2026-08-21 실측: 22건 중 6건이 여기 걸렸고, 상품동일성 의심은 11 → 5건으로 줄었다)

### 사이트별 파싱 노하우

- 다나와: `class="prc_c">금액`이 최저가. 판매처는 그 앞 `<span class="logo">디피컴</span>`
  또는 로고 이미지 `<img alt='11번가'>` 둘 중 하나다. **둘 다 받아야 판매처가 비지 않는다.**
- 본문이 800자 미만이면 JS 리다이렉트/봇벽이다 (컴퓨존은 83바이트만 준다) → 브라우저 티어로.
- 한글 포함 URL(Dell 한국몰)은 percent-encoding 해야 요청이 간다.
- 동시요청 6개면 다나와가 간헐적으로 터진다. **4개 + 1회 재시도**가 안정적이었다.

## 가격 DB (재검색 방지) — 2026-08-20 스키마 개편

**웹 검색 전에 반드시 먼저 조회한다.**

```
python .agents/scripts/price_lookup.py 9100 PRO 2TB     # 이름·스펙·모델코드 검색
python .agents/scripts/price_lookup.py --key danawa:103413458
python .agents/scripts/price_lookup.py --history danawa:94083122   # 관측 이력 전체
python .agents/scripts/price_lookup.py --stale          # 신선도 만료 = 재조사 대상
python .agents/scripts/price_lookup.py --tier D         # 투찰 근거로 쓰면 안 되는 것
python .agents/scripts/price_lookup.py --anchor Xeon 4510   # 가격 미공개 품목의 앵커
```

가격이 안 잡힐 것 같은 품목은 **`--anchor`를 먼저** 본다. 올서버 카탈로그(실판매가)와
조달몰 계약단가(상한)를 같이 됀진다. 출력의 `≤` 표시는 bound=upper라는 뜻이다.

| 필드 | 값 | 의미 |
|---|---|---|
| `bound` | `point` / `upper` / `lower` | **그 값이 단가인가 상한인가** |
| `acquisition` | `scrape` / `contract` / `quote` / `derived` / `fx` / `internal` | 어떻게 얻었나 |
| `valid_until` | 날짜 | 견적·단가표 유효기한. 지나면 tier 자동 D |
| `qty_tier` | 문자열 | 견적이 전제한 수량 구간 |
| `evidence_urls` | 배열 | 차분 역산의 근거 URL 2개 (없으면 tier D) |

**`bound`가 제일 중요하다.** 조달 계약단가·개찰 역산은 "그 가격이다"가 아니라
"그보다 비쌀 수 없다"는 **상한**이다. 상한을 상한이라 적지 않으면 다음 사람이
그걸 단가로 읽고, 그 순간 추정가가 된다(규칙 1 위반).

게이트가 막는다: `gen_analysis.py`의 `upper_bound_problem()`은 선택=O 행에
`shop.g2b.go.kr` URL이나 "계약단가/상한" vendor가 있으면 **BLOCKED**를 낸다.
만료된 견적(`quote_valid_until` 과거)도 마찬가지다. 기존 파일 감사는 `audit_prices.py`가
`상한가사용` 행으로 잡아낸다.

### 저장소 3개의 역할

| 파일 | 성격 | 수정 |
|---|---|---|
| `data/price/products.json` | 상품 **정체성** (key, name, brand, model_code, spec, urls[]) | 스크립트/수정 가능 |
| `data/price/observations.jsonl` | **관측** (누가·언제·어떻게·얼마) | **append-only. 과거 관측을 고치지 말 것** |
| `price-research/references/price-db.json` | 위 둘에서 자동 재생성되는 **파생 뷰** | **손으로 고치지 말 것** (다음 재생성에 사라짐) |

상품키는 URL에서 자동 생성된다(`danawa:103413458`). URL이 없는 당사 매입가·견적은
**채널:모델코드**를 쓴다(`internal:samsung-ssd/MZ-VAP2T0BW`, `quote:itmaya/ESC4000A-E12`).

### 신뢰도 티어 — 기준은 오직 '나중에 재현 가능한가'

| 티어 | 정의 | 쓰는 법 |
|---|---|---|
| **A** | 당사 매입가표 / 공식 견적서 | 확정 원가. 그대로 사용 |
| **B** | 판매처 **자체 상품 페이지** 실측 | 재현 가능. 마감 임박 건은 재확인 |
| **C** | 다나와 최저가 스냅샷 | 판매처·금액이 수시로 바뀜다. **투찰 전 반드시 재확인** |
| **D** | 추정 / 환율환산 / URL 없음 | **투찰 근거 금지.** 실판매가 재조사 |

**판매처 이름이 찍혔다고 다나와가 B가 되지 않는다.** 다나와는 가격비교 페이지라 최저가
순위가 계속 바뀜고, 배지가 이미 품절·판매중지된 매물을 가리키는 사례도 있다. B는
판매처 상품 페이지를 직접 열어본 경우에만 준다.

티어는 관측 레코드에도 기록되지만(`tier_at_observation`) **뷰는 항상 현행 규칙으로 재계산**한다.
티어는 사실이 아니라 판정이기 때문이다.

### 신선도
- volatility=high (RAM/SSD/GPU/CPU): 3일 이내 그대로, 4~7일 스팟 재확인, 7일 초과 재조사
- volatility=normal: 14일
- 단 GPU급은 **하루 만에도 마진 판정이 뒤집힌다**(실측 35% 변동). 투찰 직전 재확인은 필수

### 새 관측을 넣는 법
직접 JSON을 쓰지 말고 `price_schema.observe()`로 레코드를 만들어 `append_obs()` 후
`rebuild_view()`를 부른다. 매일 도는 `price_refresh.py`가 이걸 자동으로 하고,
**워크북에만 있고 DB에 없던 상품도 자동 등록**한다(예전에 40개가 새고 있었다).
