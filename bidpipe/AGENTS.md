# Electerior - 조달 입찰 마진 분석 프로젝트

나라장터·누리장터 등에서 컴퓨터/서버 등 IT 하드웨어 납품 공고를 찾아
`Format.xlsx` 양식으로 분석하고 **마진율이 높은 공고를 선별**한다.

## 절대 규칙 (항상 적용)

1. **추정가 금지.** 전 품목 실판매가+URL. 불가 항목만 "견적 필요"+견적처 기록
   - **상한값을 원가로 쓰는 것도 추정가다.** 조달 종합쇼핑몰 계약단가·개찰 역산값은
     `bound=upper`라 "그보다 비쌀 수 없다"만 뜻한다. 선택=O 행에 넣으면 `gen_analysis.py`가
     BLOCKED를 낸다. 쓰임새는 예산 역산·천장 판단·경쟁사 지도다
   - **견적은 만료된다.** `quote:true` 행은 `quote_source`와 함께 **유효기간**을 적는다.
     만료된 견적은 tier D로 강등되고 게이트가 막는다
   - 가격이 안 잡힐 것 같으면 **"견적 필요"로 넘기기 전에** `price_lookup.py --anchor`로
     올서버·조달몰 앵커를 먼저 본다 (`price-research` 스킬의 '불투명 추적 4채널')
   - 상품이 특정된 뒤의 **가격 갱신은 AI가 아니라 `price_refresh.py`가** 한다(LLM 0).
     AI는 신규 상품 발굴·규격 대조·예외 해석에만 쓴다. 상세는 `price-research` 스킬
   - **"참고 산정가"로 이름만 바꿔 우회하지 말 것.** URL 없는 금액을 선택(O) 행에 넣으면
     붙인 이름이 무엇이든 추정가다. 진짜 견적 항목은 `quote:true` + `quote_source`(업체·연락처)를
     반드시 함께 적는다
   - **규칙만으로는 안 막혔다. 게이트를 통과해야 보고할 수 있다.**
     `gen_analysis.py`는 URL 불량 행이 있으면 `gate:BLOCKED` + 종료코드 1을 내고,
     반환 JSON에 `price_basis`(추정 행수·금액·원가 대비 비중)을 싣는다.
     기존 파일 감사는 `audit_prices.py '날짜폴더/*.xlsx'`.
     **BLOCKED·보고금지 건은 마진율을 입에 담지 말 것**
     (2026-08-20: 규칙 1이 있었음에도 30건 중 28건이 위반. 생성기가 ERROR를 stderr로만
     찍고 stdout으로는 깨끗한 margin_rate를 돌려줘서 경고가 보고 경로에서 증발했다)
2. **묶음 행 금지.** 조립 PC/서버는 **부품별로**, 완제품 다품목 공고는 **명세서 순번별로** 행을 펼친다
   - 작성 후 **순번 커버리지와 총수량을 세어 원문과 대조**하고, 각 행 비고에 `명세서 N항`을 남긴다
   - (실사례 2026-08-20 원안기술원: "기타 주변기기 일괄 120만" 한 줄에 **노트북 3대(642만)**이
     묻혀 마진이 +24.3% → **-9.7%**로 뒤집혔다. 묶음 행은 판정을 바꾸는 사고다)
3. G2B Masters 1차 탐색 + **나라장터 직접 더블체크 필수** (색인 누락·상태변경 존재)
4. 공유/납품용 파일명은 **`기관명_공고명.xlsx`** (숫자 파일명 금지)
   - **저장 후 파일명의 공고번호와 워크북 기재값(B5)이 같은지 확인한다.** 어긋나면 그 공고는
     "분석했다고 믿지만 실제로는 없는" 상태가 된다
   - (사고 2026-08-21: `20260819/20260818_R26DD20847739_대구대.xlsx`가 동남보건대 파일의
     **md5까지 동일한 복사본**이었다. 대구대 R26DD20847739 분석은 존재한 적이 없다.
     파일 하나만 열어보면 정상으로 보이고, **목록으로 놓고 봐야만 보인다** — 대시보드의
     무결성 검사가 이걸 잡는다)
5. `Format.xlsx` 원본 수정 금지. 분석 파일은 날짜 폴더 `YYYYMMDD/`에 (2026-08-19부터 분석/ 대체)
6. 보고는 마진율 내림차순 표 + **가격근거 컬럼** + 리스크(견적필요/시황/자격/마감임박/OCR/규격미달) 명시 + **완화 후보**(어느 규격 조건을 풀면 마진이 크게 벌어지는지 수치화, 규칙 10)
   - **마진율 단독 표기 금지.** 추정가가 섞인 건은 `*`(잠정)을 붙이고 추정 비중을 병기한다
     (예: `53.7%* · 추정 1행 47.5%`). 원가의 절반이 추정이면 그건 마진율이 아니다
   - 추정 비중이 **원가의 30% 이상이면 마진율을 보고하지 않고** "견적 확보 전 판정보류"로 적는다
   - 표는 `audit_prices.py '날짜폴더/*.xlsx'` 출력을 근거로 만든다 (손으로 세지 말 것)
7. 낙찰하한율 명시 공고는 이율=하한율, 최저가제는 0.88/0.96 병기
   - **하한율은 공고문 본문에서 확인한다.** 기본값 88%를 관성으로 넣지 말 것
     (2026-08-20 극지연: 공고문은 "예정가격의 90% 이상"인데 88%로 계산돼 있었다).
     기초금액도 반올림 없이 공고 기재값 그대로 (부산교육청: 70,000,000 → 실제 69,994,000)
8. 선택=O 행은 RFP 전 행(특히 I/O PORTS) 대조 필수. 미확인="확인필요", 미달은 X(원가 제외)+현설 확인
   - **추출물을 먼저 믿지 말고 자가검증한다.** `extract_specs.py`가 추출 직후 번호 연속성을
     검사해 `[!] 누락의심`을 stdout으로 낸다. 경고가 뜨면 원문(PDF 변환본·미리보기)으로
     그 구간을 직접 대조하기 전에는 분석에 들어가지 말 것
   - (2026-08-20관련 2026-08-21 KAIST R26BK01690151: HWPX 파서가 `<hp:t>`의 tail을 버려
     `2) Clock speed: 6400MHz` 등 3줄이 조용히 사라졌다. '메모리 속도 미지정'으로 오판해
     규격 미달 DDR5-5600을 선택했고 **마진이 7.5%인데 11.0%로 보고**됐다.
     텍스트만 봐서는 이상이 안 보인다 — 번호를 세는 것만이 방어다)
9. **분석한 공고는 개찰 후 결과를 회수한다.** 분석→투찰로 끝나면 원가 추정이 맞았는지 영영 모른다. `outcome-tracking` 스킬 참조, 로그는 `.agents/data/outcomes/outcomes.jsonl`(append-only). 아래 규칙 10이 예전 "규칙 9"이다.
10. **규격 제약 민감도 분석(완화 제안) 필수.** RFP 규격은 "참고제품 도용"이 흔해 특정 모델의 I/O·크기·전력이 그대로 복사되고, 개별 항목(HDMI×2, RGB, PS/2, 86.4cm 등)은 임의·오타일 수 있다. 전조건 충족품이 없거나 그 원가가 예정단가 근처(마진 제로/음수)이면:
   - 어떤 1~2개 조건이 "결합"(가장 싼 후보를 배제)하는지 분리
   - 해당 조건을 완화한 시나리오에서 최적 제품을 찾아 **단가당/총액 마진 차이를 수치화**
   - 보고에 **완화 후보 + 현설 질문**으로 제시 (리스크 라벨로만 묻지 말 것) — 현설은 담당자에게 확인·완화를 이끌어내는 자리
   - I/O 행(HDMI 수, RGB, PS/2)과 크기/전력 값은 완화 후보 최상위 (참고제품 특성일 확률 높음)
11. **마진율이 높게 나온 건일수록 계약조건을 다시 판다.** 마진율은 "부품 원가 대비 투찰가"일 뿐이고,
    계약서에 숨은 이행비용·위험은 한 줄도 안 잡혀 있다. **예산이 후한 게 아니라 남들이 안 들어오는
    이유가 계약조건에 있는 경우가 많다.**
    - **대상: 마진율 20% 이상 전 건 + 금액 1억 이상 전 건 + 재공고·유찰 이력 건**
    - 규격서만 보지 말고 **공고문·계약특수조건·과업지시서·일반조건 전문**을 읽고
      `contract-risk` 스킬의 독소조항 체크리스트를 적용한다
    - 발견한 조항은 ①분석 파일 개요에 `[독소조항]` 절로 명시 ②정량화 가능하고 **견적처·단가가 있는 것은 물품 행으로 계상**(부대비용 금지, 규칙 15)
      ③불가하면 리스크로 보고. **체크 안 한 고마진 건을 "추천"으로 올리지 말 것**
    - 마진이 높은데 유찰·재공고 이력이 있으면 **사유를 반드시 추적**한다 (예산 부족이 아니라
      조건 때문에 아무도 안 들어온 것일 수 있다)
12. **원가율을 먼저 재고 들어간다.** 모델명이 지정된 리테일 완제품 공고(노트북·모니터·주변기기)는
    수요기관이 **다나와 최저가로 예산을 짜는 경우가 많다**(명세서 "상세정보"가 다나와 스펙
    표기를 그대로 복사한 형태면 거의 확실하다). 전수 조사 전에 대표 품목 2~3개만 먼저 조회해
    **예산 대비 원가율**을 재고, 90%를 넘으면 조기 종료한다
    - **손익분기 투찰율 = 총원가 ÷ 기초금액.** 이 값이 낙찰하한율보다 높으면 이길 방법이 없다
    - (실사례 원안기술원: 원가율 94.9%, 손익분기 96.5% vs 하한 88% → 구조적 적자)
    - 부품 조합 여지가 있는 GPU·서버 건과는 성격이 완전히 다르니 같은 기대를 가지지 말 것
13. **지역제한은 따지지 않는다.** (2026-08-20 사용자 확정) 본점·주된 영업소 소재지 제한
    (대전·대구경북·부산·서울경기인천 등)은 **리스크도 참가불가 사유도 아니다.**
    - 지역제한만을 근거로 공고를 제외하거나 "참가 불가", "소재지 확인 필요"로 보고하지 말 것
    - 분석 파일 참가자격 칸에는 사실만 적고(예: "지역제한: 대전"), 별도 경고 표시는 하지 않는다
    - 단, 지역과 결합된 **이행 조건**(예: "고장 시 4시간 이내 현장방문")은 여전히 비용·리스크로
      평가한다. 제한 자체가 아니라 SLA 대응체계가 포인트다
14. **대외 메일은 반드시 `일렉테리어 <hello@electerior.com>` 별칭으로 보낸다.**
    (2026-08-21 사용자 확정) 발주기관 문의·입찰·견적 등 이 프로젝트의 모든 대외 발신이 대상.
    - Gmail 계정은 `uid 0 = hello@brainware.co.kr`이 **기본값**이라 그대로 보내면
      발신자가 `브레인웨어 대표메일`로 나간다. **보내기 전 From을 일렉테리어로 바꿀 것**
    - 등록된 발신 별칭: 브레인웨어 대표메일(기본) / 비들리 contact@biddly.kr /
      **일렉테리어 hello@electerior.com** / 렌탈본점 hello@rentalai.co.kr /
      서버스테이션 대표메일 serverstation2002@gmail.com
    - **본문의 주체와 발신자 표시명을 반드시 일치시킨다.** 서명은 Gmail이 자동으로
      붙이므로 본문에 서명을 또 쓰지 말 것
    - (사고 2026-08-21 KAIST R26BK01690151 규격 문의: brainware 기본계정으로 보내고
      본문은 "일렉테리어입니다"로 시작해, 구매팀으로부터 *"메일명은 브레인웨어인데
      문의 주체는 일렉테리어여서 혼선이 발생할 수 있을 것 같습니다"* 지적을 받았다.
      발주기관과의 과거 응답 이력도 전부 hello@electerior.com 기준으로 쌓여 있다)
15. **부대비용은 원가에서 제외한다.** (2026-08-21 사용자 확정)
    부대비용은 정의상 추정치라 **규칙 1(추정가 금지)과 정면으로 충돌**하고, 건별로 자의적이라
    공고 간 마진율 비교를 깨뜨린다. 실제로 2026-08-21 0820 배치에서 부대비용 30만~300만이
    임의로 들어가 GIST 메모리건이 -1.1%를 **-12.5%로 보이게** 만들었다.
    - 마진율 기준은 **`상품가격 합계`만**이다. `gen_analysis.py`가 부대비용을 0으로 강제하고,
      값이 들어오면 `NOTE:`를 찍는다
    - 이행비용(운송·설치·출장·조립 공수·교육·보증 대응)은 **원가가 아니라 개요의 리스크 항목**으로
      적는다. 정량화되면 규칙 11의 계약조건 검토에서 다룬다
    - **견적이 붙는 실물 항목은 부대비용이 아니라 물품 행이다.**
      (예: 한밭대 3년 보증연장 2,962,300원, 설치지원 1,100원 — 판매처 단가가 있으므로 sel=O 행)

## 지식 베이스 (.agents/skills/ - 작업 전 해당 스킬 읽기)

| 스킬 | 언제 읽나 |
|---|---|
| `bid-discovery` | 공고 탐색·더블체크·검증 (G2B Masters, 나라장터, 누리장터) |
| `spec-extraction` | 첨부 다운로드, HWP/HWPX/PDF/OCR 규격서 파싱 |
| `price-research` | 시장가 조사 전 (출처 신뢰도, 견적처, `references/market-notes.md` 시황) |
| `analysis-workbook` | 분석 엑셀 생성·수정, 파일명·보고 형식 (`gen_analysis.py`) |
| `company-context` | 참가자격 판정, 회사 강점 활용 (HP 파트너, 직생확인, GPU 소싱) |
| `outcome-tracking` | 개찰결과 회수·사후 대조 (우리 원가 추정 vs 실제 낙찰가 오차) |
| `contract-risk` | **고마진·고액·재공고 건의 독소조항/계약조건 심층 검토** (규칙 11) |
| `mac-toolchain` | 파이썬 실행·도구 설치 전 (격리 문제 해결 절차, conda env) |

## 파이썬 실행

**항상 `.agents/py`를 쓴다.** (conda env `electerior`, Python 3.11.15로의 심볼릭 링크)

```bash
.agents/py .agents/scripts/gen_analysis.py 데이터.json
```

- 환경이 깨졌으면 `bash .agents/scripts/setup_conda_env.sh` (재생성은 `--force`)
- **작업 중 `"python3.11" Not Opened` 팝업이 뜼면 `Done`을 누를 것.**
  파란색 기본 버튼인 `Move to Trash`를 누르면 파이썬 바이너리가 삭제된다
- `pip install` 뒤에는 `xattr -dr com.apple.quarantine ~/.anaconda3/envs/electerior`를 붙인다
  (안 하면 numpy 등 컴파일 패키지 import가 막힌다)

## 대시보드 (2026-08-21 추가)

날짜 폴더가 사실상 DB다. 그 인덱스를 한 화면에서 마진율 순으로 본다.

```bash
./dashboard/run.sh            # → http://127.0.0.1:4180
```

- **마진 계산·추정가 감사는 `audit_prices.py`를 그대로 import해서 쓴다.** 대시보드가 자체
  계산식을 가지면 감사 규칙이 바뀔 때 조용히 어긋난다. `audit_prices.py`만 고치면 된다
- 규칙 6을 화면에서도 강제한다: 추정 30%+ 는 `판정보류`, 원가 0원은 `원가 미입력`(마진 100%가
  아니다), 계산 불가는 `판정 불가`
- **판정보류·원가 미입력 건은 마진율 정렬에서도 빠진다.** 수치를 가려도 행의 위치가 그 값을
  알려주기 때문이다. 보고하지 않기로 한 값으로 줄을 세우는 것도 보고다
- 파일 무결성(내용 동일·공고번호 중복·파일명 불일치)을 같이 검사한다 → 규칙 4
- **행을 열면 그 공고의 분석 워크북이 상세 안에 iframe으로 바로 뜼다**(2026-08-21).
  서버의 `/render` → `xlsx_render.py`가 로컬 xlsx를 HTML로 바꾸는 경로라 구글 계정·업로드가
  필요 없고, Excel에서 고친 것이 재스캔 없이 바로 보인다 (이 맥은 Excel·soffice·Quick Look이 전부 막혀 있다)
- **구글시트**(2026-08-21): 헤더의 `목록`/`시트` 버튼으로 전환. 시트는 대시보드 안에
  **iframe으로 임베드**된다(`SheetPanel.tsx`). Sheets는 `/preview`·`/edit?rm=minimal`·`/htmlembed`
  세 경로 모두 iframe을 안 막고, `edit?rm=minimal`은 대시보드 안에서 그대로 **편집까지** 된다.
  브라우저 로그인 세션을 타므로 권한 없는 계정이면 빈 화면이 뜼다
- 미러 데이터 채우기: 서버가 `127.0.0.1` 전용이라 공유가 안 돼서 같은 목록을 시트로 민다.
  대상은 `.agents/data/sheet_mirror.json`, 매트릭스는 `sheet_export.py`, 푸시는 에이전트의
  `googleSheets.writeMatrix`(파이썬은 구글 자격증명이 없어 못 한다). 표기는 화면과 **같은**
  `dashboard_view.py`를 쓰므로 규칙 6이 두 곳에서 갈라지지 않는다.
  검증은 `readSheet`가 아니라 **CSV 내보내기**(`/export?format=csv&gid=`)로 전수 대조한다
