# 공고 요약 — 실측 이력

`POST /api/notice-summary` 의 품질을 **같은 입력으로 반복 측정**한 기록이다.
프롬프트를 고칠 때마다 여기 한 줄이 늘어야 한다. `docs/opportunity-eval.md` 와 같은 규칙이다.

- 입력: `test/fixtures/notices/*.json` 3건 (물품·용역·공사)
- 실행: AI 서비스를 띄우고 픽스처를 `POST /api/notice-summary` 로 보낸다

> 픽스처는 **손으로 만든 것**이다. `docs/plan.md` M1 이 지적한 "실물 규격서 0건" 은
> 아직 해소되지 않았다 — 백엔드 DB 에서 실물을 뽑아 오면 이 표를 다시 채운다.

---

## 회차

### baseline (변경 전)

| | 값 |
|---|---|
| 성공 | **0건 / 3건** |
| 응답 | `501 NOT_PORTED` |

`item-summary`·`bid-summary` 는 합쳐서 69줄짜리 자리표시자였다. 요약 기능은 만들어진 적이 없다.

### v1 — `notice-summary-2026-08-26-v1`

| 픽스처 | 상태 | 길이 |
|---|---|---|
| 001 물품(서버구매) | 200 | 406자 |
| 002 용역(유지보수) | 200 | 175자 |
| 003 공사(전기) | 200 | 289자 |

**결함 1건.** 001 이 마지막 줄에 "첨부문서가 잘려 있음을 알립니다" 를 붙였는데
**실제로는 자르지 않았다**(예산 23,208자 중 약 700자만 사용). 프롬프트 규칙 5가
"잘렸다는 표시를 보면 적어라" 였는데 모델이 표시 없이도 적었다 — 오탐이다.
자르지도 않았는데 잘렸다고 하면 사용자가 원문을 다시 열어 확인하게 된다.

### v2 — `notice-summary-2026-08-26-v2`

규칙 5를 **`…(이하 생략)` 문자열이 입력에 실제로 있을 때만** 쓰도록 조건을 못박았다.

| 픽스처 | 상태 | 길이 | 생략 오탐 |
|---|---|---|---|
| 001 물품(서버구매) | 200 | 285자 | ✅ 해소 |
| 002 용역(유지보수) | 200 | 172자 | ✅ 없음 |
| 003 공사(전기) | 200 | 284자 | ✅ 없음 |

**잡아낸 것(육안 확인).** 세 건 모두 입찰 판단을 바꾸는 조건을 놓치지 않았다 —
물품의 *대기업 참여제한*·*장애 4시간 이내 현장 도착*, 용역의 *상주 근무 원칙*·
*지적재산권 귀속*·*인력 즉시 교체*, 공사의 *무정전 공법 필수*·*최근 3년 실적 1건*.

### v3 — `notice-summary-2026-08-28-v3`

v2 는 **공사 공고에서만** `**구매 대상**` 처럼 항목명을 볼드로 꾸몄다. 물품·용역은
평범한 불릿이었다. 요약은 화면에 그대로 렌더링되므로 **공고마다 서식이 달라 보인다.**
규칙 2에 볼드 금지를, 규칙 3에 **고정 항목명과 순서**를 못박았다.

| 픽스처 | 상태 | 길이 | 항목명 | 금액 |
|---|---|---|---|---|
| 001 물품(서버구매) | 200 | 328자 | ✅ 고정 | ✅ |
| 002 용역(유지보수) | 200 | 281자 | ✅ 고정 | ✅ |
| 003 공사(전기) | 200 | 314자 | ✅ 고정 | ✅ |

**중간에 잡은 회귀 1건.** 항목명을 고정하면서 목록에 **금액을 빠뜨렸더니** 세 건 중
두 건에서 금액 줄이 통째로 사라졌다(v2 에는 있었다). 모델은 규칙 3의 "항목명을 새로
만들지 마라"를 지킨 것이라 잘못이 아니다 — 목록이 곧 명세다. `예산·금액` 을 항목으로
넣고, 근거가 없으면 생략이 아니라 "명시 없음"을 적도록 예외를 뒀다. 금액이 없다는
사실 자체가 입찰 판단에 쓰이기 때문이다.

> 서식을 고치는 변경이 **내용을 지울 수 있다.** 항목 목록을 건드릴 때는 이전 회차
> 출력과 항목 단위로 대조할 것. `make notice` 가 그 대조를 쉽게 하려고 있다.

### 실패 경로 (v2)

LM Studio 를 끄고 호출:

```
HTTP 503  code=LLM_UNAVAILABLE  retryable=true  summary=None  requestId=있음
```

**200 에 지어낸 요약이 실리지 않는다.** `PORTING_STATUS.md` 의 과거 사고
(지어낸 요약이 `aiFallback=false` 로 200 에 실려 `analysis_history` 에 눌러앉음)가
재발하지 않음을 확인했다. `scripts/test_http_contract.py` 가 이 불변식을 건다.

## 남은 것

- **실물 규격서로 다시 측정한다.** 지금 픽스처는 손으로 쓴 것이라 길이·잡음이 실제와 다르다.
  특히 **절단 경로(`INPUT_TOO_LARGE`)가 한 번도 발동하지 않았다** — 긴 첨부가 없어서다.
- 규칙 3은 "근거 없는 항목은 생략"인데 모델은 `참가자격` 에 **"명시 없음"** 을 적었다
  (002). 규칙과 어긋나지만 출력은 더 친절하다 — 생략과 "없음"이 섞이면 읽는 쪽이
  헷갈리므로, 어느 쪽으로 통일할지 담당자 확인이 필요하다.
- 데드라인은 AI 100초 < 백엔드 120초 < 리스 300초 순으로 겹쳐 둔다. 지연은 모델과
  하드웨어에 따라 달라지므로 여기 적지 않는다 — **배포 환경에서 다시 재고 판단한다.**
