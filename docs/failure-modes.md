# 실패 분류표 — g2bmaster-AI

`Principles.md §2.1` 이 가리키는 문서다. 단일 출처는 코드(`app/errors.py`)이고,
이 문서는 **각 분류를 언제 쓰는지와 백엔드가 무엇을 해야 하는지**를 적는다.
값이 어긋나면 코드가 이긴다 — `scripts/test_errors.py` 가 **아래 §2 표를 파싱해 코드와
대조하므로**, 한쪽만 고치면 `make check` 가 깨진다.

---

## 1. 대원칙

AI→백엔드 구간에서 실패는 **정직한 4xx/5xx** 로 내린다.
HTTP 200 폴백은 백엔드 컨트롤러가 `AiUnavailableException` 을 잡아 만드는 것이지,
우리가 미리 만드는 것이 아니다(`ai-boundary.md §6.4`, `CLAUDE.md §2-1`).

우리가 200 으로 포장하면 백엔드는 실패를 구분할 근거를 잃고,
폴백 결과가 캐시에 눌러앉아 **영원히 재분석되지 않는다.**

**백엔드는 HTTP status 가 아니라 `code` 와 `retryable` 로 판단한다.**
status 는 프록시·로드밸런서·모니터링이 읽는 값이고, 분류의 진실은 본문에 있다.

---

## 2. 분류표

| code | status | retryable | 언제 | 백엔드가 할 일 |
|---|---|---|---|---|
| `BAD_REQUEST` | 400 | ✗ | 스키마 검증 실패, 깨진 JSON 본문, 본문 상한 초과 | 재시도 금지. 작업을 영구 실패로 기록 |
| `INPUT_TOO_LARGE` | 400 | ✗ | 클램프 예산이 0 — 문서가 컨텍스트 창에 전혀 안 들어감 | 재시도 금지. 문서를 줄여 재등록해야 함 |
| `TAG_MISSING` | 400 | ✗ | 서약서 워크플로에 문서 태그가 없음(첨부 접근 전) | 재시도 금지. 태그 판정은 백엔드 소관 |
| `UNAUTHORIZED` | 401 | ✗ | `AI_SERVICE_SECRET` 이 설정됐는데 헤더가 없거나 다름 | 재시도 금지. 설정 불일치이므로 배포를 봐야 함 |
| `NOT_PORTED` | 501 | ✗ | 해당 마일스톤이 아직 배포되지 않음 | 200 폴백 생성. **재시도 금지** (§3 참조) |
| `EMBEDDING_UNAVAILABLE` | 503 | ✗ | ML 스택(`requirements-ml.txt`) 미설치 | 재시도 금지. 임베딩만 막히고 나머지 표면은 정상 |
| `LLM_UNAVAILABLE` | 503 | ✓ | 엔드포인트 전멸, 워커 풀 소진, 연결 거부 | 200 폴백 생성 + 재시도 대상. `retryAfterMs` 존중 |
| `LLM_TIMEOUT` | 504 | ✓ | 데드라인 초과. 부분 결과조차 없음 | 200 폴백 생성 + 재시도. 다음엔 `deadlineMs` 를 늘릴 것 |
| `LLM_MALFORMED` | 502 | ✓ | 두 번 시도했는데도 JSON 파싱/계약 검증 실패 | 200 폴백 생성 + 재시도. 반복되면 프롬프트 문제 |
| `INTERNAL` | 500 | ✓ | 분류되지 않은 예외 = 우리 버그 | 200 폴백 생성 + 재시도. 로그로 알릴 것 |

### 응답 본문

```json
{
  "code": "LLM_TIMEOUT",
  "error": "AI 분석이 제한 시간 내에 끝나지 않았습니다.",
  "retryable": true,
  "retryAfterMs": 3000,
  "requestId": "…"
}
```

- `error` 는 **사용자에게 그대로 렌더링되는 한국어**다(`aiError`). 코드에서 조립하지 않고
  분류표에서 가져온다(`Principles §7.2`).
- `retryAfterMs` 는 있을 때만 싣는다. 없는데 0 을 실으면 "즉시 재시도" 로 읽힌다.
- 내부 진단(`detail`)은 **본문에 넣지 않는다.** 파일 경로·엔드포인트 주소가 들어가므로
  로그 전용이다.

---

## 3. `NOT_PORTED` 가 관례를 벗어나는 이유

관례상 5xx 는 재시도 가능인데 이것만 `retryable: false` 다. 의도적이다.

- **501 이어도 되는 이유** — 2026-08-06 `AiClient` 를 읽어 확인했다. `post()`/`get()` 이
  `catch (RestClientException e)` 로 잡는데, 이는 `RestClient.retrieve()` 가 4xx·5xx
  양쪽에 던지는 예외의 **부모**다. **status 로 분기하지 않으므로** 501 도
  `AiUnavailableException` 이 되고 `ai-boundary.md §6.4` 의 200 폴백이 만들어진다.
  (전에 이 절은 503 을 제안했다. 그 제안은 철회됐다 — `decisions.md F-4`.)
- **재시도 불가인 이유** — 지금 다시 불러도 결과가 같다. 마일스톤이 배포되기 전까지
  재시도는 순수한 낭비이고, 워커의 재시도 예산을 태워 큐의 다른 작업을 굶긴다.

→ 다만 **백엔드는 아직 이 본문을 읽지 않는다.** `e.getMessage()` 만 남기고 `code`·
`retryable` 을 버린다. 그래서 `retryable: false` 가 실효를 가지려면 `plan.md §8.2` 의
**R0**(본문 파싱)이 함께 가야 한다.

---

## 4. 부분 실패는 실패가 아니다

스텝 단위로 갈리는 상황(법령 검토는 됐는데 요약이 실패)은 **정상이고 200 이다**:

```json
{
  "degraded": true,
  "degradedReasons": [{ "code": "SUMMARY", "message": "요약 생성에 실패했습니다." }],
  "summary": null,
  "facts": []
}
```

`degraded` 는 백엔드에게 **"쓰되 캐시하지 말고 재시도 대상으로 둬라"** 는 신호다
(`Principles §2.2`). 값이 있다는 이유로 생략하지 않는다.

`degradedReasons[].code` 는 실패한 스텝 이름을 쓴다(`FACTS`, `SUMMARY`, `ITEMS`,
`LEGAL`), 데드라인으로 건너뛴 경우는 `DEADLINE` 이다. 이 코드들은 위 분류표와
별개의 축이다 — 분류표는 **요청 전체**의 실패, 이쪽은 **스텝 하나**의 실패다.

### 아무것도 못 만들었으면 degraded 가 아니다

부분 결과가 하나도 없는 상태로 데드라인이 지나면 `LLM_TIMEOUT` 으로 **실패**한다.
빈 결과를 200 으로 돌려주면 백엔드가 그것을 성공으로 캐시한다.

---

## 5. 재시도 겹수

백엔드에 이미 재시도가 있다(`analysis-job-queue.js`).
우리 안에서 재시도하는 것은 **같은 요청 안에서 값싸게 회복 가능한 것뿐**이다:

| 상황 | 우리가 재시도? | 겹수 |
|---|---|---|
| LLM 응답 JSON 파싱 실패 | ✓ | 1회 추가 (총 2회 호출) |
| 엔드포인트 페일오버 | ✓ (legacy 풀 내부) | 풀 정책에 위임 |
| 워커 풀 소진 | ✗ | 즉시 `LLM_UNAVAILABLE` |
| 데드라인 초과 | ✗ | 즉시 `LLM_TIMEOUT` |
| 그 밖의 전부 | ✗ | 실패로 올린다 |

두 겹 재시도는 백엔드가 계산하는 ETA 와 비용 예측을 전부 무너뜨린다(`Principles §4.4`).

**이 겹수를 고정하는 테스트는 아직 없다.** 예전엔 `test/fault/gateway.test.ts` 가
호출 횟수로 묶어 뒀지만 그 구현은 TypeScript 와 함께 지워졌고, 재시도하는 코드 자체가
아직 이식되지 않았다. LLM 호출 경로를 옮길 때 호출 횟수 테스트를 함께 넣는다.

---

## 6. 시간 부등식

```
AI 자체 데드라인  <  g2b.ai.timeout-ms  <  백엔드 리스 시간
```

우리가 리스를 넘기면 다른 워커가 같은 작업을 다시 집고, 우리는 여전히 추론 중이다.
LLM 비용이 두 배로 나가고 결과는 하나만 채택된다(`Principles §4.2`).

집행 지점 두 곳:

1. 라우트가 `deadlineMs` 에서 자체 여유(2초)를 빼고 `Deadline` 을 만든다.
2. 게이트웨이가 `min(남은 시간 - 1초, perCallCapMs)` 를 LLM 호출 예산으로 준다.
