# 사업기회 분류 — 실측 이력

`app/opportunity.py` 의 분류 품질을 **같은 입력·같은 정답으로 반복 측정**한 기록이다.
프롬프트를 고칠 때마다 여기 한 줄이 늘어야 한다. 숫자가 없는 개선은 개선이 아니다.

- 입력: `test/KBID_0806_사업기회분석.xlsx` 의 `전체마스터` 726건 (2026-08-06 수집분)
- 정답: 그 워크북에 사람이 배정해 둔 `자회사` 열
- 실행: `python scripts/analyze_opportunities.py test/KBID_0806_사업기회분석.xlsx`

정답 자체가 완전하지 않다는 점을 먼저 적어 둔다 — 726건 중 **363건이 `확인필요`** 로
분류되지 않은 채 남아 있다. 그래서 지표가 둘이다.

| 지표 | 무엇을 보는가 |
|---|---|
| **일치율** | 사람이 배정한 353건에서 같은 답을 냈는가 |
| **신규발굴률** | 사람이 못 가른 363건에서 자회사를 지목했는가 |

일치율만 보면 "사람을 흉내내는가"만 재게 되고, 이 업무에서 실제로 돈이 되는 쪽은
`확인필요` 더미에 묻힌 건을 건져 올리는 두 번째다.

## 회차

### v1 (2026-08-07) — 프로토타입, 저장소 밖 스크립트

| | 값 |
|---|---|
| 일치율 | 76.5% (353건 중 270건) |
| 신규발굴 | 363건 중 163건 (44.9%) |
| 미분석 | **10건** |
| fit High | 워크북 85건 → 엔진 391건 |

**드러난 결함 넷.** 셋은 프롬프트, 하나는 코드다.

1. **렌탈본점을 계약 형태로 정의했다.** "임차·렌탈이면 품목 무관"이라고 썼는데, 실제
   렌탈본점 36건 중 이름에 임차/렌탈이 있는 것은 20건뿐이고 나머지는 **세탁기·냉장고·
   정수기·제습기·커피머신 구매**다. 이 회사의 축은 계약 형태가 아니라 **생활가전**이다.
   모델은 준 정의를 충실히 따라 "가전제품으로 그룹사 품목 아님"이라 답했다 — 규칙대로 맞은 오답이다.
2. **업무구분이 자회사 판정을 덮었다.** "공사·용역이면 자회사는 확인필요"라는 규칙을 넣었는데,
   나라장터에서 **정수기 임차는 '용역'으로 올라온다.** 주력 품목이 규칙에 걸려 21건이 날아갔다.
3. **fit 기준을 말로만 줬다.** High 가 85 → 391 로 부풀었다.
4. **배치 응답의 유실을 세지 않았다.** 10건씩 묶어 보내면 모델이 항목을 빠뜨리는데,
   그 자리가 조용히 `None` 으로 남아 726건 중 10건이 사라졌다.

### v2 (2026-08-07) — `app/opportunity.py` 로 이식

프롬프트 `opportunity-2026-08-07-v2`. v1 의 넷을 고쳤다.

- 렌탈본점을 **생활가전**으로 다시 정의하고, 그 밖의 품목은 계약이 임차·렌탈일 때만 포함
- 업무구분과 자회사를 **따로 판정**한다. 용역·공사여도 자회사 판정을 덮지 않는다
- fit 등급 기준을 명문화 (High = 서버스테이션 주력 + 렌탈본점 전체)
- 빠진 자리를 골라 **재요청**하고, 그래도 비면 `RunStats.missing` 에 센다
- 값 집합 밖의 응답(`자회사: "없는회사"`)은 폐기하고 `rejected` 로 센다 —
  조용히 통과시키면 집계가 오염된다

측정값은 `test/out/*_AI분석.xlsx` 의 요약 시트에 이식 전과 나란히 실린다.

## 남은 것

- **드론이 일렉테리어에 있다.** 워크북은 드론·안티드론건을 `AV·방송` 으로 묶는다.
  일관된 패턴(해당 건 전부)이라 v2 프롬프트에 "촬영·감시용 드론"을 넣었지만,
  **사업 담당자 확인이 필요하다.** 실제로 취급하지 않는다면 빼야 하고, 그러면 일치율이
  그만큼 내려간다 — 정답 쪽이 틀린 경우다.
- **첨부를 못 본다.** 지금 판정은 공고명·기관·금액·계약방법뿐이다. 규격서를 열면
  달라질 건이 `확인필요` 에 많다. 백엔드 첨부 파싱이 들어오면 다시 측정한다.
- **HTTP 표면이 아니다.** 이 분류를 백엔드가 부르게 하려면 `CLAUDE.md §8` 대로
  `docs/decisions.md` 에 적고 합의해야 한다. `item-summary` 의 items 스텝에 얹을지,
  별도 표면으로 열지가 정해지지 않았다.
